Paso 4 — Ejercicio de especificidad

Sneider Alvarez Santos · ficha 3428392 · 15 de septiembre de 2026

1. El enunciado

Tres reglas CSS apuntan al mismo elemento. Solo se declara color, para que lo unico que compita en la cascada sea la especificidad y no otras propiedades.

2. El fragmento

/* css/especificidad.css — seccion 1 */

#aviso-1  { color: var(--color-error);   }   /* regla 1 */
p.aviso   { color: var(--color-success); }   /* regla 2 */
.aviso    { color: var(--color-info);    }   /* regla 3 */

El elemento sobre el que compiten las tres:

<p class="aviso" id="aviso-1">Texto de prueba</p>

3. La prediccion escrita

Prediccion: gana la regla 1, la que usa #aviso-1, y el texto se ve rojo (#B3261E).
Por que: la especificidad se compara antes que el orden del archivo. Un id vale 101 puntos, y le ganan un tipo y una clase (11) y una sola clase (10). Gana la regla escrita de primera.
La trampa: si se hubiera contestado «gana la ultima regla escrita», se habria equivocado, porque la ultima es la mas debil de las tres.
Segundo caso: el segundo parrafo no lleva id, asi que la regla 1 queda descartada. Alli gana la regla 2, p.aviso, y el texto se ve verde (#15803D).

4. Comprobacion en el navegador

Regla, selector, tipo de selector y puntos de especificidad
Regla Selector Que aporta Puntos Color
1 #aviso-1 1 id (1,0,0) = 101 #B3261E
2 p.aviso 1 tipo + 1 clase (0,1,1) = 11 #15803D
3 .aviso 1 clase (0,1,0) = 10 #15506B

Los dos recuadros de abajo son el mismo elemento con distinto atributo. Los colores salen del render real del navegador, no de la prediccion:

Con id — compiten las 3 reglas Gana la regla 1: #B3261E

Sin id — compiten las reglas 2 y 3 Gana la regla 2: #15803D

Resultado medido: el primer parrafo se renderiza en #B3261E y el segundo en #15803D. Los dos colores coinciden con la prediccion, asi que la prediccion era correcta. Ademas ninguno de los dos casos se resolvio con !important: la cascada normal ya basta cuando se conoce el orden de especificidad.
